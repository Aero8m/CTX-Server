## 实现边界与关键选择

### 认证和事务

- 浏览器 Cookie 仅携带随机会话标识；会话、验证码、配对码和设备凭证均使用摘要查找，稳定密钥通过环境注入。
- 管理端写操作统一校验账号会话及 CSRF。设备 Bearer 凭证不能调用管理端接口。
- 限流和验证码消费使用独立事务，因此登录失败或注册失败不会撤销限流次数，也不会恢复已消费的验证码。
- 修改设备归属、配对和发布遵循账号行锁顺序；请求成功时统一提交，任何错误回滚业务事务。
- MySQL 模型显式指定 InnoDB、utf8mb4，并包含唯一约束、必要外键和通道／修订／尝试次数检查约束。

### 发布与同步

- 可编辑草稿与不可变发布内容分开保存。规范化后的发布文本直接存储，下载摘要不受 MySQL JSON 键重排影响。
- 预览 token 绑定请求、资源修订和内容、实际目标设备；确认时重新核对，避免未确认的分组变化进入发布。
- 同一账号的发布幂等键永久绑定原操作；请求重试返回同一批次。历史回滚创建新版本和新代次。
- 每个设备的课表、配置拥有独立目标及已应用状态。回执按分配和尝试序号去重，旧回执不会替换当前目标或降低已应用代次。
- 本机手动选择、清理过期安排不使相同分配重复覆盖；新分配按完整档案下发。Qt 必须独立保存云端标记。
- 模拟设备保存内容和回执日志，验证回执丢失、重启、保存失败、编辑阻塞、离线及撤销后重新配对。

### 契约与前端

- 请求校验位于 `backend/ctx_server/schemas.py`，响应模型位于 `responses.py`；导出契约和生成的 TypeScript 随代码提交。
- 后端测试同时核对实际响应与响应模型；OpenAPI 测试核对接口清单与注册路由，避免文档遗漏。
- 前端导入文件先调用只校验接口，成功后才渲染；网页编辑器直接修改草稿，保存前本地检查并再次调用校验接口，失败按错误路径切换页签。保存冲突保留当前内容，可下载本地表单或档案再合并；未保存关闭和文件替换都有确认。
- 设备和发布状态 10 秒刷新，页面隐藏时暂停；移动端保留导航、账号和退出入口，宽表格可横向滚动。
- 管理端提供使用教程、全局请求加载遮罩及淡入淡出，后台刷新保持静默；页面、弹窗和组件排序具有轻量过渡，并遵循系统减少动态效果设置。
- Element Plus 首版使用独立公共包，构建会提示约 921 kB 的压缩前公共 chunk；gzip 约 297 kB，页面模块已按路由分包。
